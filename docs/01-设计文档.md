# Gili Agent 设计文档

> 版本：v0.1（原型阶段）｜日期：2026-08-05｜状态：设计定稿，逻辑待接入

## 1. 产品定位

**一句话**：一个"专门属于我"的个人 AI 伙伴 —— 本地运行的可视化 WebUI Agent，目前只对接 DeepSeek，把**前缀命中率**和**记忆**做到极致，未来演进为个人学习知识库。

**三阶段演进**：

| 阶段 | 主题 | 能力 |
|---|---|---|
| 一（当前） | 对话伙伴 | 可视化 WebUI、DeepSeek 深度优化（前缀命中率 + 记忆）、对话与数据全本地 |
| 二 | 对话收藏 | 一键收藏"有意思"的对话，导出为 markdown 永久保存 |
| 三 | 学习知识库 | 笔记系统（markdown 文件）+ 大纲系统 + 学习 agent（贴资料 → 自动生成大纲/笔记/复习卡片） |

**核心用户场景**：

- 场景 A｜日常陪伴：跨天持续聊天，AI 记得我聊过什么、我的偏好
- 场景 B｜有意思对话收藏：聊得好的内容一键沉淀，永不丢失
- 场景 C｜学习新知识（未来）：把资料丢给它，产出大纲、笔记，随时问答检索

## 2. 设计原则

1. **前缀稳定性是第一公民** —— PromptBuilder 与记忆系统都围绕它构建，而不是事后优化
2. **数据归用户所有** —— 对话存 SQLite（便于查询），收藏对话与笔记导出为 markdown 文件（可被 Obsidian 打开）
3. **先可观测、后优化** —— 命中率/成本/延迟全程可见，任何优化都有数据支撑
4. **渐进式架构** —— 现在只挂 DeepSeek，LLMProvider 留好抽象，未来可扩展

## 4. 核心设计一：前缀命中率

### 4.1 机制认知（摘要）

DeepSeek 的上下文缓存是**自动的、按前缀的、按块匹配**的：请求的 prompt 前缀与之前完全一致的部分命中，命中输入价格约为未命中的 **1/10**。**前缀只要有一个块变了，它之后的所有缓存全部作废。** 你**无法强制命中**，唯一可控的杠杆是请求结构（见 docs/02-技术文档.md 第 3 节）。

### 4.2 Prompt 分区固定顺序

```
稳定区（永不变化）        低频区（阈值触发才重写）        波动区（每轮追加）
[System/人设] [工具定义] [固定 few-shot]  [长期记忆摘要]  [近期历史] [当前用户消息] [时间戳/检索]
└────────────── 缓存永远保住 ──────────────┘  └────── 前缀逐轮命中 ──────┘ └─绝对尾部─┘
```

> v0.19 修正（docs/12）：动态内容（时间戳/检索）必须挂**绝对尾部**（当前消息之后），
> 插在历史与当前消息之间会让下一轮的新历史占据该位置 → 前缀链断裂（实测命中率 13.5% → 82%+）。

### 4.3 三件套（参考 pi-deepseek-cache 的实现模式）

1. **Prefix Guard（前缀守卫）**：守卫稳定区，拒绝易变内容（时间戳、随机 ID、动态注入）混入；每次组装后校验分区字节稳定性
2. **Hit-rate Telemetry（命中率遥测）**：每请求读取 `usage.prompt_cache_hit_tokens / prompt_cache_miss_tokens` 落库，仪表盘实时展示；命中率 < 0.4/小时视为异常告警
3. **Cache-friendly Compaction（缓存友好压缩）**：历史超预算时从开头**整条丢弃**（不截断半句），被丢内容由摘要兜住；摘要只在超阈值时重写，重写即缓存失效要记账

### 4.4 反模式清单（禁止）

- ❌ 在 system 里注入"当前时间/日期" → 每请求必变，缓存全灭
- ❌ 每轮重写记忆摘要 → 等价于每轮清缓存
- ❌ 随机打乱 few-shot 顺序 / 工具 schema 每次序列化不同
- ❌ 从中间裁剪历史消息 → 破坏块对齐

## 5. 核心设计二：三层记忆

| 层 | 内容 | 更新频率 | 在 prompt 中的位置 |
|---|---|---|---|
| 核心记忆（core） | 人设、不可变规则 | 几乎不动 | 稳定区最前 |
| 工作记忆（working） | 近期 N 轮对话，按 **token 预算**裁剪（非条数） | 每轮追加 | 波动区 |
| 长期记忆（longterm） | 滚动摘要 + 抽取的事实/决定（结构化 JSON） | 每 K 轮或阈值触发批量写 | 摘要进低频区 |

关键联动：**摘要低频重写 = 缓存连续性**。历史 token 累积超过 `summary_rewrite_threshold` 才触发一次压缩，两次重写之间前缀完全不动，命中率可达 90%+。

记忆操作入口：WebUI 记忆面板可增删改查、手动触发压缩 —— 把"命中率优化"变成肉眼可见的实验。

## 6. 数据模型

**SQLite（阶段一/二）**：

| 表 | 字段要点 |
|---|---|
| `conversations` | id, title, created_at, updated_at, params_snapshot |
| `messages` | id, conversation_id, role, content, tokens, created_at |

## 7. WebUI 设计

三栏布局：

```
┌──────────┬───────────────────────────────┬────────────────┐
│ 会话列表   │       聊天区（流式）            │ 参数 │记忆 │数据  │
│ 新对话    │   header: 标题 / 收藏导出 / 清空 │ ─────────────  │
│ c1  ...  │   messages 滚动区               │ 模型选择        │
│ c2  ...  │   输入框 + 发送                 │ temperature... │
│          │                                │ 记忆参数        │
│ 状态点    │                                │ 记忆三层列表     │
│          │                                │ 命中率仪表盘     │
└──────────┴───────────────────────────────┴────────────────┘
```

- **参数面板**：模型（deepseek-v4-pro / deepseek-v4-flash，1M 上下文）、思考（模式开关 + 强度 low/high/max，V4 独立旋钮，思考时采样参数不生效）、temperature、top_p、max_tokens、presence_penalty、frequency_penalty、流式开关；记忆参数（历史 token 预算、摘要重写阈值、记忆检索开关）
- **思考过程可视化**：流式渲染 `reasoning_content` 为浅色"💭 思考中…"块（真实模式）
- **Markdown 渲染**：助手消息支持表格/代码块/Mermaid 流程图，消息右上角随时切换「源码 / 渲染」视图（marked + DOMPurify + mermaid，多 CDN 兜底，全部加载失败自动降级纯文本）
- **记忆面板**：三层记忆可视化 + 增删改 + 手动压缩按钮
- **数据面板**：命中率曲线、累计 tokens、估算成本、平均延迟、请求日志表（每行 hit/miss 明细）

## 8. 设置系统

**入口**：侧边栏 ⚙ 按钮 → 设置弹窗。

| 设置项 | 说明 |
|---|---|
| API Key | 密文输入，存 `data/settings.json`（已 gitignore，永不进代码/日志）；接口回显打码 `sk-abc…wxyz` |
| Base URL | 默认 `https://api.deepseek.com`，预留自建网关场景 |
| 默认模型 | deepseek-chat / deepseek-reasoner |
| 测试连接 | 调 DeepSeek `/models` 接口验证 key（0 token 消耗），成功列出可用模型 |
| 人设（Soul） | 自由编辑 —— 即核心记忆，进稳定区，永不变化 |

设计说明：**即使只有 DeepSeek 一个模型，设置页也是硬需求** —— key 必须能存、能换、能测。多 Provider 选择不做（阶段后续再扩展）。
未配置 key 时：聊天自动回退 MockProvider，页面标识「原型模式」；配置后切换「真实模式」。

## 9. Skill 系统（可开关能力）

**定位**：可开关的能力模块。每个 Skill = 名称 + 描述 + 静态提示词片段 +（可选）动态注入部分。

**与缓存的关系（核心设计点）**：

- 技能**开启后**，静态片段合并进【稳定区】→ **技能开关 = 稳定区变化 = 缓存失效** → 切换必须记账（cache_invalidated），建议在对话间隙切换
- 技能片段按**注册表顺序**确定性合并（不随开关顺序变化），保证字节稳定
- 技能中的**动态内容**（如时间戳）绝不进稳定区 —— 由 PromptBuilder 注入【波动区】

**v1 技能清单**：

| id | 名称 | 说明 | 状态 |
|---|---|---|---|
| time | 时间感知 | 知道当前日期时间（动态时间戳注入波动区） | ✅ 实现 |
| coder | 程序员模式 | 编程问答更严谨，给出可运行示例 | ✅ 实现 |
| learner | 学习模式 | 阶段三：笔记/大纲/知识库 | 占位（灰显） |
| search | 联网搜索 | 阶段三：搜索工具 | 占位（灰显） |
