# 对话人格画像系统设计（大五 + 行为维，八维雷达）

> 版本：v1.0 ｜ 日期：2026-08-14 ｜ 状态：设计定稿，待实施
> 前置阅读：docs/05（记忆系统）、docs/06（学习模式）——本系统复用其「后台分析节奏」与「会话级隔离」模式

## 1. 背景与目标

Gili 的定位是「专属 AI 伙伴」。记忆系统解决了「它记得我说过什么」，本系统解决「它懂我是什么样的人」：随对话推进，每 20 轮对会话文本做一次风格分析，用**大五人格框架**输出八维画像（0-100 分）+ 证据摘录 + 快照时间轴，最终以八角雷达图可视化。

设计目标：

| 目标 | 说明 |
|---|---|
| 默认关闭 | 零打扰、零成本；用户主动开启才生效 |
| 会话级独立 | 每个对话各自积累自己的画像数据；关闭即删除（"关闭就没"） |
| 定期自动分析 | 每 20 轮一次后台分析，无需用户操作 |
| 可观测可解释 | 每个维度附对话原文证据，不输出"黑箱分数" |
| 独立模型 | 可配独立 API Key/Base URL（默认复用主 key + v4-flash） |

## 2. 定位红线（重要）

1. **这是"画像估计"，不是心理测评**：基于对话文本的大五推断 ≠ 标准量表测量。所有界面明示：「基于本对话文本的画像估计，仅供自我观察，非临床测评」。
2. **不贴标签**：每个维度呈现为"高分端 ↔ 低分端"的双侧特征描述，不说"你好/你坏"。
3. **数据只属于会话**：快照存本会话名下，不跨会话聚合，删除会话级联删除。
4. **画像不进对话提示词**（v1）：纯展示系统，不反向影响回复风格（避免"自我实现预言"）。进 prompt 是 P2 可选项。

## 3. 八维度定义

### 3.1 核心五维（经典大五）

| # | 维度（key） | 高分端 | 低分端 |
|---|---|---|---|
| 1 | 开放性 openness | 好奇探索、爱新想法、抽象思考 | 务实、偏好熟悉、具体落地 |
| 2 | 尽责性 conscientiousness | 条理自律、目标明确、计划性强 | 随性灵活、顺其自然 |
| 3 | 外向性 extraversion | 热情健谈、乐于互动、从交流中获得能量 | 内敛安静、偏好独处、表达克制 |
| 4 | 宜人性 agreeableness | 合作体贴、易共情、优先考虑他人 | 直率有主见、敢于反对、竞争意识 |
| 5 | 情绪稳定性 stability | 情绪平稳、抗压、不内耗 | 敏感、易焦虑、情绪起伏明显 |

### 3.2 行为三维（对话文本最可观察）

| # | 维度（key） | 高分端 | 低分端 |
|---|---|---|---|
| 6 | 表达详尽度 verbosity | 长篇展开、喜欢解释原理 | 简洁直接、点到为止 |
| 7 | 主动质疑 questioning | 频繁追问、挑战结论 | 接受为主、跟随引导 |
| 8 | 幽默戏谑 humor | 爱开玩笑、反讽、玩梗 | 严肃正式、就事论事 |

### 3.3 评分约定

- 每维 0-100 整数；50 = 无明显倾向
- LLM 需同时输出**证据摘录**（每维 1 条最典型原文引用 + 所在消息 id）
- 输出一句话**整体摘要**（summary）

## 4. 分析机制

### 4.1 触发节奏

- 复用「海马体」模式：chat 成功后（真实 provider、非 regen），累加本会话用户消息轮数
- 轮数 % 20 == 0 且开关开启 → asyncio.create_task 后台分析（不阻塞主回复）
- 轮数计数持久化（重启不丢）；开关开启后的第一次分析从开启点起算，不够 20 轮不分析

### 4.2 分析输入与成本控制

- 首份快照：本会话全部用户消息
- 后续快照：上一份快照结果（先验）+ 最近 20 轮消息（增量迭代，画像平滑演变）
- 每条消息截断 300 字，总输入 ≤ 6000 token；思考关闭、temperature 0.2、max_tokens 1200
- 成本：每 20 轮一次小调用（flash 约 ¥0.01 级），可忽略

### 4.3 LLM 输出契约

只输出 JSON：

    {
      "dims": {"openness": 62, "conscientiousness": 58, ..., "humor": 41},
      "evidence": [{"dim": "openness", "quote": "……原文……", "message_id": "m..."}],
      "summary": "一句话画像概述"
    }

- 解析失败/缺维 → 该维置 50（中性）+ 日志记录；整体失败 → 丢弃本轮、等下 20 轮（不重试轰炸）

### 4.4 独立模型

- 设置新增：画像模型名 / 画像 API Key / 画像 Base URL（全部可空）
- 全空 = 复用主 key + v4-flash（默认，零配置可用）
- 填了独立 key → 独立 AsyncOpenAI 客户端（复用 llm.py 的共享客户端缓存，按 key+base 区分）
- 独立调用失败 → 回退主 provider + 日志（画像不因换 key 失效而中断）

## 5. 数据模型（SQLite）

### 5.1 表结构

    persona_snapshots
      id TEXT PK
      conversation_id TEXT       -- 会话作用域
      turn_no INTEGER            -- 第几轮时生成
      dims TEXT                  -- JSON {"openness":62, ...8 维}
      evidence TEXT              -- JSON [{dim, quote, message_id}]
      summary TEXT
      model TEXT                 -- 本次分析用的模型（审计）
      created_at TEXT

    persona_state
      conversation_id TEXT PK
      enabled INTEGER DEFAULT 0  -- 开关（默认关）
      user_turns INTEGER DEFAULT 0  -- 已计轮数（开启时才开始累计）
      updated_at TEXT

索引：persona_snapshots(conversation_id, turn_no)。

### 5.2 生命周期

- 开启开关：persona_state.enabled=1，轮数从 0 起计
- 关闭开关：删除该会话全部快照 + 状态行（"关闭就没"）
- 删除会话：级联删除（现有 delete_conversation 追加两行）

### 5.3 与现有系统边界

- 与记忆系统互不读取：海马体抽取"事实"，画像分析"风格"，两个后台任务独立
- 快照不进 knowledge_chunks/FTS（不参与知识检索）
- 不进 prompt 稳定区/低频区/波动区（v1）

## 6. API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/persona/{cid} | 画像状态：{enabled, turns, snapshots: [...]} |
| POST | /api/persona/{cid}/toggle | {enabled} 开关；关闭时后端删快照 |
| POST | /api/persona/{cid}/analyze | 手动触发一次分析（调试/等不及 20 轮） |
| GET/PUT | /api/settings | 增加 persona_model / persona_api_key / persona_base_url（key 打码/加密走现有 secrets） |

### 7.2 八角雷达图

- 自绘 canvas（复用命中率曲线经验，新增 drawRadarChart）
- 8 轴按 §3 顺序排布；快照对比模式：选中两个快照 → 两个多边形叠加
- 维度名/分值标注；50 分中圈虚线

### 7.3 快照时间轴

- 横向 chip 列表：第20轮 第40轮 …（灰色=未到，亮色=已有快照）
- 点快照 → 雷达图与 8 卡切到该快照；默认显示最新
- P2：点击证据摘录 → 滚动到对应消息并高亮

### 7.4 设置页

- 设置弹窗新增「画像模型」区块：模型名 / API Key（密文输入）/ Base URL
- 提示文案：「留空 = 复用主 Key（v4-flash）；每 20 轮仅一次小调用」

## 8. 工程与缓存边界

- 后台分析用独立 provider（见 4.4），复用 llm.py 共享客户端（按 key+base 缓存，不新增连接池泄漏）
- 分析请求不进 _last_routed 前缀复用体系（输入是画像专用拼装，非主请求前缀）
- 快照读写仅在开关开启/分析/查看时发生，对聊天热路径零影响
- 分析任务异常：log.exception 落盘（沿用日志系统），不影响主回复

## 9. 实施计划

### 阶段 A：核心闭环

1. db：两表 + 迁移 + 级联删除 + 状态存取
2. persona.py（新模块）：轮数计数/触发判断/分析引擎（拼装+调用+解析+落库）/toggle 清理
3. main.py：chat 成功路径挂触发；/api/persona 三端点；settings 三字段
4. 前端：面板按钮 + 弹层骨架 + drawRadarChart + 8 维度卡 + 开关 + 时间轴（基础版）
5. 测试：分析引擎（FakeProvider 全路径/坏 JSON 降级/增量先验）、toggle 清理、级联删除、轮数持久化

### 阶段 B：体验增强

1. 快照对比叠加雷达图
2. 证据点击跳转消息（滚动+高亮）
3. 画像模型设置 UI 完善（测试连接按钮）

## 10. 验收标准

- [ ] 默认关闭：不开启时零调用、零界面打扰
- [ ] 开启后 20 轮 → 第一份快照（8 维分 + 8 证据 + 摘要）；40 轮 → 第二份，时间轴可切换
- [ ] 关闭 → 快照与状态全删；再开启从零开始
- [ ] 会话隔离：A 会话的画像不影响 B 会话
- [ ] 独立模型：填独立 key 走独立客户端；独立调用失败回退主 key 且不报错
- [ ] 八角图渲染正确、8 卡两端描述完整、「非临床测评」明示可见
- [ ] 重启应用：轮数与快照不丢
- [ ] pytest + smoke + check-ui 全绿（新增画像相关用例）
