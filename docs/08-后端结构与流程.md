# 后端全景文档（结构与流程）

> 这是给后续维护者（包括未来的自己）看的内部文档，不追求产品化措辞。
> 当前版本对应：记忆共享组 / 知识检索引用 / AI 决策式学习引导 已上线。

## 1. 模块地图与依赖方向

```text
main.py（FastAPI 路由 + SSE 编排）
  ├─ config      —— settings.json 读写
  ├─ schemas     —— Pydantic 请求契约（ChatRequest / ChatParams / MemoryParams / MemoryItem）
  ├─ db          —— SQLite 持久层（唯一允许直接碰 sqlite 的模块）
  ├─ llm         —— LLMProvider 抽象：MockProvider / DeepSeekProvider
  ├─ prompt_builder —— 三区提示词组装 + 前缀指纹
  ├─ memory      —— 三层记忆 + 事实抽取 + 摘要压缩
  ├─ knowledge   —— 知识分块 / FTS5 检索 / 重排 / 引用元数据
  ├─ learning_skill —— 学习引导状态机（AI 决策提问 + 项目创建）
  ├─ search      —— 联网搜索
  ├─ skills      —— 可开关技能注册表
  └─ metrics     —— 请求日志 / 命中率 / 成本
```

依赖方向（禁止反向）：

```text
db / schemas ← everything
llm ← memory, knowledge, learning_skill, main
knowledge ← db, schemas
learning_skill ← db, knowledge, schemas
main ← 全部
```

注意：`learning.py` 是遗留文件，**已不再被 main 引用**，学习逻辑全在 `learning_skill.py`。改学习模式时不要动错文件。

## 2. 数据层（SQLite）

文件：`data/gili.db`，WAL 模式。`db.init()` 幂等：建表 → `_migrate()` 增量加列 → FTS 初始化。

关键表：

| 表 | 作用 |
|---|---|
| conversations | 会话；`memory_group` 为共享组 id（NULL = 独立，默认） |
| messages | 消息 + 版本组 + `quick_options` + `sources`（引用来源 JSON） |
| memory_items | 三层记忆：core / working / longterm；kind=fact/summary |
| learning_projects | 学习项目，`conversation_id` 绑定专用对话 |
| learning_chapters / questions / notes_meta | 章节 / 疑问 / md 元数据 |
| knowledge_chunks | 可检索知识块（note/memory/chapter/question） |
| knowledge_fts | FTS5 虚拟表（trigram），content/title/heading |
| request_logs | usage / 命中率 / 延迟 / 缓存失效 |

### 迁移不变量

- `_migrate()` 用 `PRAGMA table_info` 判断缺列再 `ALTER`，必须保持幂等。
- FTS5 虚拟表**不支持 ALTER**：改索引列只能 `DROP TABLE knowledge_fts` 再重建 + `rebuild`。内容表 `knowledge_chunks` 不受影响。
- 触发器和 FTS 都失败时静默回退 LIKE 检索，聊天主流程绝不能因检索层崩溃。

### 删除级联（重要）

`delete_conversation` 现在负责四件事：

1. 删 messages
2. 删该会话 memory_items
3. 删该会话的知识块（孤儿记忆块）
4. 删会话；若其共享组剩余 < 2 人，自动解散组

## 3. 记忆作用域（本版核心语义）

默认**每个对话独立**：

- 一个会话可见的 fact = 本会话的 fact + `conversation_id IS NULL` 的手动全局 fact + 所有 core 事实；自动抽取（海马体）的 fact 会带上来源会话的 `conversation_id`，因此默认不会跨新对话泄漏。
- `memory_group` 非空时，作用域扩展到组内所有会话的 fact。
- summary（会话摘要）**不跨组**，只属于原会话，避免上下文膨胀。
- 知识检索（knowledge）对 memory 块使用同样的作用域过滤。

实现位置：

- `db.get_memory_scope(cid)` → 可见会话 id 列表
- `memory.get_context` 先过滤 facts 再做常驻/检索分拣
- `knowledge.search(conversation_id=...)` 把 scope 下推到 SQL

## 4. 三区提示词与缓存

`prompt_builder.build_prompt` 组装顺序（逐字节稳定）：

```text
稳定区   [system: 人设 soul + 技能静态片段]
低频区   [system: 摘要 + core/longterm 事实]   ← 指纹覆盖到这里
波动区   [历史原文] [环境信息 volatile] [相关记忆] [知识来源] [当前消息]
```

- 指纹 = SHA256(稳定区 + 低频区)，变化 = 缓存失效并记账。
- 知识来源永远放波动区尾部，**不进指纹**。
- 学习项目总览（`learning_skill.context_text`）也在 volatile；按问题命中的具体片段在【知识来源】。

## 5. 核心流程

### 5.1 POST /api/chat

```text
regenerate? → 定位目标 AI 消息，上下文截断到它之前
    ↓
学习引导进行中? → _learning_intercept（走状态机，不调 LLM）
    ↓
memory.get_context（按记忆作用域）→ 摘要/常驻/检索事实
    ↓
knowledge.search（FTS5 BM25 → 可选重排 → 1200 token 预算）
    ↓
build_prompt + 插入【知识来源】system 消息
    ↓
联网技能开启 → 非流式工具探测 → 执行 web_search → 续接流式
    ↓
SSE: start → params → [tool] → delta(reasoning/content) → done
    ↓
落库 user/assistant 消息（含 sources）
    ↓
后台：AI 起标题 / 每 3 轮事实抽取 / 超阈值摘要压缩
```

done 事件字段：`usage / cache_invalidated / message_id / version_group / version_no / versions_count / sources`。

### 5.2 学习引导（learning_skill）

状态按会话存在内存 `_onboard`，重启即丢（对话消息已落库，历史引导仍可显示，但不能继续推进——可接受）。

```text
start → 第一问固定「想学什么？」(input=true)
answer → 记录 → _decide_next(LLM)
         ├─ ask:    生成下一问（可选项/自由输入）
         └─ confirm: 输出计划摘要
answer(确认) → phase=done
create_project → LLM 生成章节 JSON → DB + notes/*.md → knowledge.reindex_project
```

降级：MockProvider / 决策失败 → 固定三问回退；最多 6 轮强制收束。章节生成失败可再次确认重试。

### 5.3 知识索引（knowledge）

- 分块：md 按 `#` 标题 + 段落/句号切 300 字，重叠 40；记忆整条一块。
- 查询：`_terms` 分词 → FTS5 trigram（≥3 字/英文）+ LIKE 兜底（2 字）→ 合并分数 → 可选 LLM 重排 → token 预算。
- 写入钩子：项目创建、记忆新增/删除；存量靠 `ensure_*_indexed` 懒补 + `python -m app.knowledge --reindex-all`。

## 7. 深度审计记录（本回合）

发现并已修复：

1. 删除对话后共享组残留：组内计数会变成「共享组 1」，现已级联解散。
2. 删除对话后记忆知识块孤儿：调试检索会翻出已删会话的记忆，现已级联清理。
3. FTS5 缺 `heading` 索引时尝试 `ALTER TABLE` 会失败并静默禁用 FTS：已改为「重建虚拟表 + rebuild」。
4. 打开会话时先等学习项目列表再拉消息，导致卡片点击延迟：已改为并行，消息先渲染。
5. 会话列表每次刷新整列重建 + 首屏错落延迟偏高：已加签名缓存（数据未变只切选中态），并降低动画延迟。
6. 学习工作室点击卡片时列表整列重建、详情强制空转 loading：已加列表签名缓存 + 详情缓存，重复点击直接返回。
7. 多选栏按钮过多挤压：已收敛为「全选 + ⋯ 菜单（连接记忆/删除/退出）」，菜单点外部自动收起。

仍需留意的已知边界（不视为 bug）：

- `_onboard` 状态在内存：服务重启后未完成的学习引导只能重开。
- summary 不跨共享组：这是有意取舍，避免多个会话的压缩摘要混在一起。
- 知识引用依赖模型输出 `[编号]`；模型没写编号时，来源抽屉仍可用。
- 真实 DeepSeek 网络路径未在开发沙箱验证，重排/抽取/压缩都保留 mock 回退。

## 8. 本回合新增（密钥 / 学习闭环 / 消息管理）

- **密钥加密**：`app/secrets.py` 用 Windows DPAPI（本机 + 当前用户），存储格式 `enc:v1:<base64>`；非 Windows 明文回退。`config.load` 自动解密，`config.save` 自动加密；GET /api/settings 只回打码值，POST /api/settings/reveal-key 才回真实值。
- **学习推荐**：普通对话点学习模式 → `learning_skill.recommend` 分析最近对话给推荐计划 → 「✅ 确认创建 / ✍️ 重新填写」。确认直接建项目，重新填写回到首问。
- **学习档案闭环**：学习对话每 2 轮用户消息后 `propose_update` 判断是否学完某章，生成建议气泡；`handle_update_answer` 确认即打勾、更新进度百分比、可选补笔记并重建索引。建议回答在 chat 路由里优先拦截（`has_pending_update`）。
- **删除**：DELETE /api/learning/projects/{pid}（保留对话）；DELETE /api/messages/{mid}（删整组版本）。
