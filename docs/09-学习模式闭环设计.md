# 学习模式闭环设计（对话 ↔ 学习档案双向联动）

> 状态：已评审通过，按此实现。
> 背景：当前学习对话只能“读”档案（大纲/进度/疑问），档案无法因聊天而更新，导致所有项目进度长期为 0；学习对话缓存前缀也偏短，命中率不高。

## 1. 目标

1. 学习对话支持显式命令推进学习：开始章节 / 完成章节 / 记笔记。
2. 工作室与左侧学习侧栏的章节可手动勾选，与聊天双向同步。
3. AI 建议气泡降级为兜底，并支持“我学的其实是别的章节”。
4. 学习项目总览（大纲/章节状态/疑问）进入低频缓存区，提升学习对话命中率。

## 2. 交互契约（聊天命令）

学习项目绑定后的普通消息，先做命令识别（不调 LLM）：

| 用户输入 | 行为 |
|---|---|
| `开始第 3 章` / `学第 3 章` | 设置当前章节，回复“开始学习第 3 章 X” |
| `开始下一章` | 当前章之后第一个未完成章节；无则回复全部完成 |
| `第 3 章学完` / `本章学完` | 打勾、更新进度百分比、重建索引、建议下一章 |
| `记一下：内容` / `笔记：内容` | 追加到当前章节笔记，无当前章则追加到项目笔记.md |
| `问一下：内容` | 追加到疑问本 |

未命中的消息继续走正常 LLM 聊天。

## 3. 工作室 / 侧栏

- 章节列表每行：完成状态勾选框 + 「开始」按钮。
- 勾选/取消 → PUT 章节状态 → 项目进度、知识索引、低频区上下文同步刷新。
- 「开始」→ 写入对话一条系统消息，设置 current_chapter，侧栏切到对话视图。
- 侧栏章节行同样可勾选、可点「开始」。

## 4. AI 建议气泡（兜底）

- 保留每 2 轮用户消息判断一次的节奏。
- 选项改为：`✅ 标记完成` / `📖 我学的是别的章节` / `↩ 暂不`。
- “别的章节” → 回复待选章节列表，用户发章节序号后打勾。
- 自定义文本优先解析 `第 N 章`；否则当作补充笔记。

## 5. 缓存分区调整

- `prompt_builder.build_prompt` 新增 `lowfreq_text` 参数（低频区 system 消息，进入指纹）。
- 学习项目总览：学科/水平/风格/章节状态/疑问列表 → `lowfreq_text`。
- 笔记摘要、按问题检索到的知识片段 → 波动区，维持现状。
- 打勾/档案变化 → 低频区指纹变化一次（可接受，且会记 cache_invalidated）。

## 6. API 增量

```text
PUT  /api/learning/chapters/{chapter_id}        {status, note?}
POST /api/learning/chapters/{chapter_id}/start  开始章节（写对话消息）
POST /api/learning/projects/{pid}/notes          {content, kind: note|question}
```

聊天命令拦截返回 JSON：`{"mode":"learning_command","status":"ok","command":...}`。
