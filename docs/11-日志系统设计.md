# 日志系统设计（开发者可见，v0.15.2）

> 日期：2026-08-14 ｜ 状态：已实施 ｜ 零依赖（stdlib logging）

## 1. 目标与非目标

**目标**：给开发者（含后续接手的 AI）一个稳定的排查入口——桌面模式关窗后现场不丢、后台任务异常带堆栈落盘、约定统一。

**非目标**：
- 不做用户可见的日志面板（数据面板的请求日志表已覆盖「给用户看的指标」）
- 不做结构化 JSON / 集中采集 / request id 追踪（个人单机场景过度设计，规模到了再说）
- 不记录聊天内容全文（隐私与体积；要调试 prompt 用请求查看器，未做则临时 DEBUG）

## 2. 输出与位置

| 输出 | 级别 | 位置 | 滚动 |
|---|---|---|---|
| 控制台 | INFO+ | stdout（桌面版 bat 窗口 / uvicorn 终端） | — |
| 文件 | DEBUG+ | `data/logs/gili.log` → `.1` → `.2`… | 1MB × 5 份，UTF-8 |

- `data/` 已在 .gitignore，日志永不进版本库
- uvicorn 的错误（启动失败/未捕获异常）并入文件；access 噪音不进
- 初始化幂等（`app/log.py::setup_logging()`，由 `main.py` 模块级调用，desktop.py 经此自动生效）

## 3. 级别约定

| 级别 | 用途 | 示例 |
|---|---|---|
| DEBUG | 临时排查（用完删或降级） | 分词细节、检索候选数 |
| INFO | 关键节点（低频） | 启动行、chat 开始/完成（cid/model/hit/miss/用时） |
| WARNING | 可恢复异常 | 上传文本提取失败、联网搜索失败 |
| ERROR/EXCEPTION | 必须注意的失败 | 后台任务异常一律 `log.exception`（自动带堆栈） |

## 4. 红线与约定

1. **绝不记录 API Key / Tavily Key**（config.py 的加载/保存路径不打印任何密钥字段）
2. 模块内统一 `log = logging.getLogger(__name__)`
3. 后台任务（`asyncio.create_task` 的 _safe_*）异常用 `log.exception`——这是桌面模式下唯一能留下的现场
4. `desktop.py` 的用户可见启动进度仍用 print（那是给用户看的，不是给开发者看的）

## 5. 排查速查

```powershell
# 实时看（开发模式）
Get-Content data\logs\gili.log -Tail 50 -Wait

# 查后台任务异常
Select-String -Path data\logs\gili.log* -Pattern 'extract-facts|auto-summarize|auto-title|chat-error'
```
