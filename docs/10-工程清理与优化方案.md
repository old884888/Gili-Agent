# 工程清理与优化方案（v0.15.1 工程卫生批次）

> 版本：v0.1 ｜ 日期：2026-08-14 ｜ 状态：实施中（批次按编号执行，每批独立提交可回滚）

## 1. 背景与目标

v0.15 功能稳定，但工程侧积累了一批债：`static/app.js` 经多轮"整段追加重写"长到 3824 行且含大量被覆盖的旧实现；`app/learning.py` 是已替换模块的死代码；已知边界清单（开发日志 §5）里还有几个低成本可闭环的 stub。本方案只做**清理 / 优化 / 修复**，不引入新功能、不重构架构，核心承诺：

- **行为等价**：清理后的产品行为与 v0.15 完全一致（除修复项外）
- **可回滚**：git 基线快照 + 每批一次提交
- **可验证**：每批都有语法检查 / 接口冒烟 / 人工核对脚本

## 3. 清理项设计

### 3.1 C1：app.js 重复定义去除（核心改动，需安全论证）

**为什么安全**：同名顶层 `function` 声明会整体提升（hoisting），**后者覆盖前者**，与声明位置无关；删除前面的旧定义，全程序行为不变。全文件 106 处顶层函数声明经逐行人工核对（无模板字符串/嵌套误判），92 个函数名中 13 个存在重复，其中 14 个旧定义待删：

| 函数 | 待删定义 | 保留（生效）定义 |
|---|---|---|
| renderMessageContent | @112 | @227 |
| toggleMarkdown | @127 | @213 |
| setMultiMode | @145 | @3312 |
| updateMultiCount | @155 | @480 |
| renderSkills | @774 | @1583 |
| loadConversations | @810 | @2338 |
| openConversation | @902 | @3455 |
| ensureReasoningBlock | @1000 | @2550 |
| addReasoningBlock | @1017 | @2572 |
| appendMessage | @1102、@2580 | @3342 |
| sendChat | @1284 | @2675 |
| loadLearningProjects | @2164 | @2832 |
| openLearningCenter | @2171 | @2842 |

**边界规则**：每个旧定义只删除「声明行 + 其缩进 body」，函数体之间夹着的**顶层语句**（0 缩进，如按钮接线、`const input = $("#input")` 等）是活动代码，一律保留。删除后立即跑 O2/O3 验证。

**不做**：不删除"仅被顶层语句引用"的函数（可达性分析显示 92 个函数全部可达，无死函数可安全删除）；不合并/重写 v1 与 v2 逻辑（重构风险超出本批次收益）。

### 3.2 C2/C3/C4：死代码与缓存产物

- 删除 `app/learning.py`（先再次 grep 确认零引用）
- 删除 `app/__pycache__/`（.pyc 会随运行重建，git 已忽略；删除只清陈旧残留）
- 移除 `skills_market.py` 的 `from . import db  # noqa: F401`（db.init 由 main.py 负责，此 import 无副作用依赖）

### 3.3 C5：无关目录

- 已全部加入 .gitignore（deepseek-harness/、.claude/、.agents/、两个 chrome profile、*.lnk），**实体文件不动**——是否删除由用户确认（涉及他项目数据，本批次不碰）。

## 4. 修复项设计

### 4.1 F1：记忆编辑真实化

后端（main.py）：新增 `PUT /api/memory/{item_id}`，body 为 `{content?, importance?}`；调用已有的 `db.update_memory_item`；编辑后同步知识索引（`knowledge.delete_source + reindex_memory`，因 chunk 内容变化）。低频区变化 → 前缀指纹变化 → 下次请求自动记账 cache_invalidated（现成机制）。

前端（app.js renderMemoryItem）：✏️ 按钮从 stubNote 改为**内联编辑**——内容区换成 textarea + 保存/取消，保存走 PUT，成功后 `loadMemory()` 刷新并 toast。摘要（kind=summary）条目同样可编辑（内容直改）。

### 4.2 F2：成本估算含输出 token

`metrics.py` 的 `_PRICING` 增加 `output` 价：flash 0.56、pro 1.74（= 未命中价 × 4，参照 DeepSeek v3.2 输入/输出比，**占位估算**，注释标明以官网为准）。`record()` 把 `completion_tokens` 计入成本（推理 token 已含在 completion 内，不重复计）。请求日志表结构不变（只改 cost 值口径）。

### 4.3 F3：uploads 自动清理

`main.py` 启动时（`db.init()` 后）执行 `_cleanup_uploads(max_age_days=7)`：扫描 data/uploads，删除 mtime 超过 7 天的文件。个人量级、启动时跑一次即可，不做后台定时。

### 4.4 F4：会话删除时清理内存态

`delete_conversation` 已有 `_prefix_fps.pop`，补充 `learning_skill.clear(cid)` 与 `learning_skill._user_turns.pop(cid, None)`（该模块已有 clear() 接口，仅需接线）。

### 4.5 F5：health 模式动态化

`/api/health` 的 mode 改为按 `config.load()` 是否配 key 返回 `"real"` / `"prototype"`（与前端模式标识一致，不影响 status-text 显示逻辑）。

## 5. 工程化措施

### 5.1 git 策略

- ✅ 基线提交：`chore: v0.15 基线快照（清理优化开工前）`（35 个文件）
- 之后每批一次提交（feat/fix/chore 前缀），批次间失败可 `git revert` 或 `git checkout` 单文件回滚

### 5.2 O2：回归脚本 scripts/check-ui.mjs

零依赖 Node 脚本（node ≥ 18 直接跑）：
1. **孤儿 id 核对**：提取 app.js/ui.js 里 `$("#id")`、`getElementById` 等引用，与 index.html 实际 id 对照，输出"引用但不存在"清单（历史 TypeError 事故的回归红线）
2. **重复定义检查**：顶层同名 function 声明检测，发现即报错（防止"整段追加"复发）

### 5.3 O3：每批验证流程

1. `node --check static/app.js`（前端语法）
2. `python -m py_compile app/*.py`（后端语法）
3. 启动 uvicorn 冒烟：health/config/settings/memory/metrics/skills/market/learning 8 个核心端点逐一 200
4. 前端改动附 scripts/check-ui.mjs 全绿
