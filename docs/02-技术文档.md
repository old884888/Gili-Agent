# Gili Agent 技术文档

> 版本：v0.1（原型阶段）｜日期：2026-08-05
> 本文记录技术选型、DeepSeek 接入要点、前缀命中率与记忆的优化方法论，以及全部调研参考链接。

## 1. 技术栈决策

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.12 + FastAPI | async 原生，SSE 流式天然支持；社区大 |
| LLM SDK | `openai` SDK + `base_url="https://api.deepseek.com"` | DeepSeek 是 OpenAI 兼容协议，零成本接入 |
| 前端 | 原生 HTML/CSS/JS（零依赖） | 原型阶段不需要构建链；数据面板用自绘 canvas 迷你图表 |
| 存储 | SQLite（阶段一/二） | 零配置、本地、单文件 |
| 笔记 | markdown 文件（阶段三） | 数据归用户，可被 Obsidian 打开，生态互通 |

## 2. DeepSeek API 接入要点

- 协议：OpenAI 兼容（`POST /chat/completions`），用 `openai` SDK 改 `base_url` 即可
- 模型（2026-07 换代）：`deepseek-v4-pro`（旗舰，$0.435/M 未命中）/ `deepseek-v4-flash`（轻快，$0.14/M 未命中），均 1M 上下文；旧名 `deepseek-chat`/`deepseek-reasoner` 已于 2026-07-24 弃用（临时路由到 v4-flash 对应模式，代码里已做自动迁移）
- 采样参数：`temperature`、`top_p`、`max_tokens`、`presence_penalty`、`frequency_penalty`（DeepSeek 推荐 temperature=1.0, top_p=1.0）
- **思考模式（V4 独立旋钮）**：`extra_body={"thinking": {"type": "enabled"/"disabled"}}` + 顶层 `reasoning_effort`（low/high/max，默认 high，实际仅 high/max 两真档）；关闭思考时不要带 reasoning_effort；**思考开启时采样参数不生效**；思维链走 `reasoning_content` 字段流式返回；`usage.completion_tokens_details.reasoning_tokens` 提供推理 token 明细
- **关键 usage 字段**（缓存优化的数据源）：
  - `usage.prompt_cache_hit_tokens` —— 命中的输入 token 数
  - `usage.prompt_cache_miss_tokens` —— 未命中的输入 token 数
  - 流式响应需传 `stream_options={"include_usage": true}`（或读取最后一块）
- 价格：命中输入价 ≈ 未命中输入价的 **1/10**（具体价目以 DeepSeek 官网为准，接入前需核对）

## 3. 前缀命中率优化专题（核心）

### 3.1 机制认知

- 缓存是**自动**的（无需任何 flag）、**按前缀**匹配、按块（约 64 token/块）存储
- 命中是 **best-effort** 的：缓存生命周期不保证（通常几小时到几天），**不可强制命中，不要把命中率当 SLA**
- 唯一可控的杠杆是**请求结构**：让前缀逐字节稳定

### 3.2 三件套实现模式（参考 pi-deepseek-cache）

**① Prefix Guard（前缀守卫）**
- 稳定区只允许：System/人设 + 工具定义 + 固定 few-shot
- 拒绝进入稳定区：时间戳、随机 ID、每轮变化的检索上下文、轮次编号
- 工具 schema 序列化必须确定性（key 顺序固定、缩进固定）
- 组装后校验：对稳定区做哈希，变化即报错（比运行时发现缓存失效早）

**② Hit-rate Telemetry（命中率遥测）**
- 每请求记录：`hit_tokens / miss_tokens / prompt_tokens / latency / cost`
- 命中率 = hit / (hit + miss)；**命中率 < 0.4/小时视为异常**（大概率有动态内容混入了前缀）
- 命中率恒为 0 → 优先检查稳定区是否有注入

**③ Cache-friendly Compaction（缓存友好压缩）**
- 历史超预算：从开头**整条丢弃**（不截断半句，避免破坏块对齐）
- 摘要重写低频化：超过 `summary_rewrite_threshold` 才触发，重写 = 缓存失效，要记账
- 压缩用确定性输入（temperature=0）产生摘要，摘要内容哈希缓存，跨会话复用
- 部署/改 prompt 后：发 3~5 个预热请求再让真实用户上线（warm cache）

### 3.3 反模式与修复对照表

| 反模式 | 后果 | 修复 |
|---|---|---|
| system 里注入当前时间 | 每请求缓存全灭 | 时间戳放用户消息附近（波动区） |
| 每轮重写记忆摘要 | 等价于每轮清缓存 | 阈值触发重写 |
| 随机打乱 few-shot | 随机前缀 = 零命中 | 固定顺序；要多样性就注册多个固定模板 |
| 工具 schema 序列化不稳定 | 字节微差即失效 | 确定性 JSON 序列化 |
| 从历史中间截断 | 破坏块对齐 | 整条从开头丢 |
| 动态内容（时间戳/检索）插在历史与当前消息之间 | **下一轮新历史占据该位置 → 前缀链断裂，命中率锁死在稳定区**（v0.19 实测 13.5%→82%） | 动态内容一律挂当前消息之后的**绝对尾部** |

### 3.4 监控阈值建议

- 命中率 < 40%（1 小时窗口）→ 告警，检查前缀
- P95 延迟翻倍持续 5 分钟 → 检查是否缓存失效
- 429 率 > 5%（1 小时）→ 限流重试（指数退避 + 抖动）

### 3.5 技能开关与缓存稳定性

技能开启时其静态片段进入【稳定区】，**开关即缓存失效**。因此：
a) 技能在对话间隙切换；b) 切换记入 cache_invalidated 指标；c) 技能片段按注册表顺序确定性合并（不随开关顺序变化）；d) 技能中的动态内容（如时间戳）由 PromptBuilder 注入【波动区】，禁止进稳定区。

## 4. 记忆方案

### 4.1 三层结构（设计见 01-设计文档.md 第 5 节）

- **核心记忆**：人设/规则，稳定区
- **工作记忆**：近期历史，按 token 预算裁剪（`history_token_budget`），波动区
- **长期记忆**：滚动摘要 + 抽取的事实/决定（结构化 JSON），低频区

### 4.2 方案选型（2026-08 调研结论）

| 方案 | 结论 | 理由 |
|---|---|---|
| [Mem0](https://github.com/mem0ai/mem0) | **阶段二首选，当库调用** | Apache 2.0、API 简单、自托管、抽取-存储式记忆层，~7k tokens/对话，省 2~3 天 |
| [Letta (MemGPT)](https://github.com/letta-ai/letta) | 借鉴架构思想 | 内存分层（RAM/硬盘）思想即我们三层记忆的来源；但它是完整运行时，做底座太重 |
| [Zep / Graphiti](https://github.com/getzep/graphiti) | 不选 | 需要 Neo4j，企业级重量，个人项目过重 |
| [Hindsight](https://github.com/vectorize-io/hindsight) | 关注 | LongMemEval 评测第一（94.6%），多策略混合；新项目，API 稳定性待观察 |

**注意**：Mem0 会丢弃原文（抽取后原始消息不留存）——我们的 `messages` 表永远保留原文，抽取只作为长期记忆的来源，两套并存。

### 4.3 检索

- 起步：SQLite FTS5 全文检索（零依赖）
- 后续：向量检索（中文场景建议 bge-m3 等中文优化嵌入模型），本地跑或 API

## 5. 观测与监控

- **阶段一/二**：自绘仪表盘（`request_logs` 表 + 前端 canvas 图表）——够用且零依赖
- **数据量大了再考虑**：[Langfuse](https://github.com/langfuse/langfuse) 自托管（MIT，无功能门槛，追踪+成本），用 SDK 接入
- 不选 Helicone：2026-03 被收购后进入维护模式，不适合新项目

## 7. 风险与注意事项

1. **缓存是 best-effort**：不要假设命中；成本估算以未命中兜底
2. **价格变动**：DeepSeek 价目表可能调整，接入前核对官网
3. **隐私**：对话/记忆全本地存储，DeepSeek API 请求不可避免出网（API key 放环境变量/本地配置，不进代码）
4. **命中率与延迟的权衡**：追求命中率而让摘要过度滞后会伤害对话质量——阈值是可调参数，仪表盘上观察权衡
5. **API Key 存储**：存 `data/settings.json`（gitignore 忽略），接口回显打码，日志永不打印 key
